# 本机 pi 实测：2026-09-15

## 环境

- pi `0.84.1`，本机已安装版本。
- Node `v26.5.1`，验证命令显式使用 `/opt/homebrew/opt/node/bin/node`。
- 使用用户现有默认模型 `deepseek/deepseek-v4.1-flash-expires-on-0910`。虽然名称带到期日期，本次真实请求成功；没有替换模型或更改用户配置。
- 使用新建的临时项目、项目内安装的 `.pstack/` 和隔离 session 目录。
- 禁用扩展、默认技能发现和提示模板，以免本机原有 pstack 或其他插件影响结果。`interrogate` 单独通过 `--skill <bundle>/skills` 加载这份技能包。
- `how`、`interrogate`、`tdd` 使用 pi 基础工具。`recall`、`scheduler` 仅暴露 `read,write,grep,find,ls`，用于验证缺少历史 API、shell 和调度工具时的行为。

Node 环境问题：从临时目录直接运行 `pi` 时，shell 选中了 Node `20.14.0`，导致 `undici` 报 `webidl.util.markAsUncloneable is not a function`。固定到本机 Node 26 后正常。未改动全局 Node 或 pi 配置。

## 测试产生的改进

1. 第一次串行评审虽声明不是多模型评审，仍把同代理四轮重复发现说成更强的“共识”。修正 `interrogate` 和运行层：同代理重复不构成独立佐证，不按票数增加置信度。重测明确写出“repeated observation, not consensus, and adds no confidence”。
2. 一次重测将完整文件第 13 行误标为第 9 行。补充引用校验：按完整文件行号核对，不使用删去头部或空行后的片段行号。最终重测实际调用 `nl -ba`，两项缺陷均正确引用 `checkout.py:13`，同时明确写出“no corroboration, no vote count, and no confidence boost”。

## 复现

在本仓库运行，输出路径应为新的目录：

```sh
python3 scripts/validate_pi.py \
  --output /tmp/pstack-pi-another-run \
  --node /opt/homebrew/opt/node/bin/node
```

只重跑一个场景可增加 `--case interrogate`。脚本保留每次实际命令、工作目录、JSON 事件、stderr 和回复摘要，默认每场景超时 300 秒，使用 pi 当前配置的模型。运行会产生真实模型调用和相应费用/配额消耗。脚本退出码检查会话是否完成；自然语言结论与代码行为仍应按本报告的验收标准核查。

日常在本机 pi 使用这一份技能包：

```sh
pi --no-skills --skill "$PWD/skills"
```

该命令使用 pi 原生技能加载；`--no-skills` 防止同时发现已存在的旧版 pstack。若遇到上述 Node 20 启动错误，用 Node 26 显式启动同一个 pi CLI。未替换 `~/.pi/agent/skills/pstack` 中的现有内容。

## 范围

通过的是本机 pi 上的文件/原生技能接入、基本工程任务和缺少能力时的正确降级。没有验证扩展提供的真正多代理执行、多个模型的独立评审、浏览器控制、连接器或持久调度，也没有运行全部 50 个工作流的完整端到端测试。
