# 本机 pi 新增技能实测：2026-10-05

## 环境与范围

- 本机 pi 0.84.1，通过显式 Node 26 启动；用户当前模型 `deepseek/deepseek-v4.1-flash-expires-on-0910` 的真实请求成功，未修改全局设置。
- 全新临时项目安装当前 `.pstack/`，禁用扩展、默认技能发现、提示模板和主题，使用隔离 session 目录。
- 本次执行 `benchmark-checklist` 与 `correct` 两个新增流程；两个会话均实际读取 `pstack-runtime`，退出码 0，有 `agent_end` 且无模型错误。
- 验证采用有意构造的本地夹具，结论来自源码、工具事件和独立复查。它不是盲测，也不代表全部 53 个技能或其他 harness 均已端到端验证。初版五场景的证据保留在 [9 月报告](pi-2026-09-15.md)。

## 结果

| 场景 | 观察与独立核查 | 结果 |
| --- | --- | --- |
| 无效性能提升 | baseline 生成字节列表，candidate 返回未消费的 generator；pi 实际检查类型、完整产出、重复测量和独立 profile，指出候选在计时区间做了零次序列化。最终将真实导出速度判为 inconclusive，未修改夹具 | 通过限定验收 |
| 重复错误治理 | 用户提供两次格式列表漂移记录；pi 先重现 JSON 被拒绝，再让 CLI 从注册表推导支持格式。新增 5 个测试含独立字面值断言；主验证进程重跑全部通过。独立临时副本恢复旧列表及把 exporter 改为返回 None，两种变异都被测试拒绝 | 通过 |

`correct` 保留了用户提供的纠正记录，只改作用域内的 CLI、回归测试和 AGENTS.md 规则表，没有提交，也没有编造过去的提交或聊天历史。

性能答复中的诊断计时和经验性的速率推断不作为端到端速度排名或硬件上限证据。通过的结论是“原测量无效，真实导出速度证据不足”。没有把诊断微基准当成生产导出验证。

## 实测带来的改进

1. 首轮正确识别跳过工作，仍把诊断耗时说成“不更快”。新增显式区分：可以证明原测量无效，但缺少实际用户路径等证据时不能据此证明等速或更慢。重测结论以 inconclusive 明确回答真实导出速度。
2. 首轮纠正测试只比较两个生产函数，两个函数同时返回 None 仍可通过。补充独立输出断言和 no-op 变异检查；重测的 JSON/CSV 字面值断言均能拦住空实现。

## 复现

```sh
python3 scripts/validate_pi.py \
  --output /tmp/pstack-pi-another-october-run \
  --node /opt/homebrew/opt/node/bin/node \
  --case benchmark --case correct
```

输出路径必须是新的目录。脚本保留调用、事件和回复摘要；退出码只表示会话完成，仍需按上述行为核查结论。机器可读摘要见 [本次证据](pi-evidence-2026-10-05.json)。首轮和重测原始数据分别留在本机 `/tmp/pstack-pi-20261005/` 与 `/tmp/pstack-pi-20261005-retest/`，未发布完整聊天记录。
