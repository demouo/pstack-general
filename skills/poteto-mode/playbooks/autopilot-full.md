### Autopilot-full

Run independent PRs through build, verification and authorized merge. Read pstack-runtime before execution. The operator's named items and explicit gates remain with the operator.

1. **Frame and persist.** A request to state a plan is not a request to execute it. Once execution is authorized, save the queue, objective, scope, done predicate, model policy and merge permissions under `.pstack/state/<run>/`. Resolve the supported PR tool or forge once, per Opening a PR. Give each writer an isolated branch/worktree. Keep independent changes off a shared stack; serialize genuine overlap.
2. **Own and checkpoint each PR.** One role owns build, first push, a draft PR while proof is incomplete, self-proof, skeptical review-bot triage, deslop, no-comments, CI and babysit. Publish the first authorized snapshot early and each later verifiable unit with hooks on. Keep a decision trail and `children.tsv` with each child's ID, state and expected runtime based on observed runs. Run repository-required pre-review checks on the committed head; hooks alone are not proof. Rebase before the first code-ready report and babysit, then preserve that merge base during fix rounds. Rebase again only for merge preparation, an actual trunk conflict, or a CI failure caused by trunk drift. Updating an owned branch after a rebase uses the authorized forge flow or `--force-with-lease` after checking its remote tip; never rewrite a shared branch or exceed host permissions.
3. **Start a verification round at code-ready.** Once shipped code is final, report its head SHA. Every later push that changes the patch starts another round. Self-proof, CI and babysit may run alongside independent verification. Merge-ready reports the exact head and receipts after those checks finish. A returned role's next round uses a fresh worker with consolidated scope unless costly live state requires reuse, per poteto-mode.
4. **Verify the round.** Give verifiers the exact head/base SHAs, full brief and measurement method when relevant. Lanes rerun gates, prove load-bearing behavior through the available app driver, compare the scenario on trunk, and audit the diff and receipts. Use at least two distinct audit focuses for complex changes, such as consumer parity, lifetimes/races, or data/config safety. A missing trunk feature is an explicit gap with a head-only behavior gate, not a fabricated comparison. Aggregate all proven findings into one fix request, including defects filed as notes. Require a failing regression covering the same defect sites, or a reproducible receipt when a test is impractical; carry that defect into the next brief. Same-agent serial fallback does not satisfy an independent merge verdict. Reuse results only under Shipping's patch-id/artifact-equivalence rule.
5. **Prepare and merge the verified head.** Audit merge-ready receipts before accepting the verdict. Merge preparation begins after round verification starts and ends with a rebase onto current trunk. Report any new SHA and wait for CI on it; recheck the verdict under Shipping. Before the authorized merge, fetch trunk and verify a clean `git merge-tree`, and check that intervening trunk changes overlap neither PR paths nor paths selecting its CI. If either check fails, rebase, report, rerun CI and reevaluate the verdict. Otherwise a later trunk move alone need not restart the rebase cycle. Merge only with the user's merge authorization, required independent verdict and forge approvals. The owner returns; a fresh owner takes the next queue item. Operator-owned items stop at merge-ready.
6. **Audit the whole program.** An hourly audit is the default suggestion. Register it only through an available authorized scheduler; otherwise run bounded in-session checkpoints and leave a handoff. Read the installed playbook and persisted objective at each tick. Count actual side effects: commits, pushes, PR/check deltas and receipts. Inspect live status through the host when available and every owner's `children.tsv`. A worker that errors or exceeds its measured runtime without progress is stuck; stop it where supported, record its state and replace still-needed work with a fresh scoped worker. A failed stop does not transfer write ownership: isolate the replacement before it writes. Do not drop work because a worker stalled. Finish accounting for all children even after the final merge. Record budget/gate countersigns only when standing authorization and the actual approval contract permit; never bypass forge approvals. Report newly observed tracked changes, completion, failure or operator gates. Unchanged ticks update the trail quietly unless the user requested periodic status.
7. **Honor stop immediately.** Send zero-write holds through available controls, stop new work and save a resumable checkpoint. With no delegation, apply the hold in this session. Resume only on the operator's instruction.

**Reply:** queue, owners, head SHAs and verified rounds; what merged; open gates and missing capabilities; abandoned/stuck work and recovery; state and decision-trail paths. Source counts from records. Do not claim a future tick without a registered scheduler.
